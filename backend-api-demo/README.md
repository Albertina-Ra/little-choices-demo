# 订单整理 API 演示

这是自制作品，不是客户项目。示例26条记录和金额全部虚构。浏览器实际请求本地Python服务；页面本身不执行清洗规则。

需要 Python 3.10 或更新版本，无第三方依赖。在本目录执行：

```powershell
python server.py --port 8876
```

打开 http://127.0.0.1:8876 。点击“整理这份CSV”，样例应显示输入26、保留21、重复1、待核对4。再点击“重发同一请求”，服务请求ID不变，replayed为true。改动文本后仍重发原请求，返回409；创建新的整理请求则按新内容处理。删除必需列可观察400校验错误。

## 接口

- `GET /api/health`：服务状态及实际执行的整理请求数。
- `GET /api/sample`：虚构CSV样例。
- `POST /api/cleanup`：JSON请求体只含csv文本，必需Content-Type为application/json及Idempotency-Key请求头。成功返回处理摘要、明细、重复及异常记录。
- 同一个请求号绑定完全相同的CSV文本。进程内最近128个请求号可复用；不同内容同号返回409，服务重启后记录清空。并发同号通过互斥区防止重复执行。
- 请求限制256KB、1000行。未知路径404，错误JSON/列结构400，不匹配的请求格式415，超限413。字段校验失败的业务记录保留到异常清单。

复用原有订单规则：店铺+流水号为主键，同主键相同内容去重，冲突组全部待核对；金额按分处理，订单号保持文本。源码在order_engine.py，来自同一工作区已验证的数据整理工具副本，原文件未修改。

本演示仅监听127.0.0.1，不调用第三方API。没有生产认证、持久幂等存储或公网部署，不能将本地验证表述为生产交付或线上客户验收。
