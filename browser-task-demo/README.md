# 浏览器小流程：自制案例

本案例为AI辅助开发的自制演示，使用虚构数据，非客户交付案例，未连接Facebook、社媒账号或真实发布接口。

演示界面通过普通网页控件模拟“生成预览—人工确认—执行—读取回执”。状态仅在页面内存里，刷新即清空。Node执行器单独保存任务状态；同一个任务编号和内容成功后不会再次点击，内容不同会拒绝，异常、取消或结果不明会停止，等待人工核对。停止任务没有自动恢复按钮，以免误重试结果不明的操作。

## 文件与使用

- `index.html`：可直接打开的自制测试页面。页面“发布”只更新本页的演示记录。
- `runner.mjs`：独立的任务状态机、JSON状态存储与普通Playwright适配器。仅允许明确的演示URL及可见控件，不读取浏览器登录存储。
- `iab-port.mjs`：通过已授权的官方内置浏览器控制普通网页控件，不创建其他浏览器连接。
- `test-runner.mjs`：14项有意义的状态机测试，包括无确认零操作、预览变化、重复任务、取消、队列中断、磁盘恢复和文件锁。
- `VALIDATION.md`：实际完成的验证及限制，未写入完成状态的检查不视为通过。

运行纯逻辑检查：`node --test test-runner.mjs`，不安装浏览器，不联网。

文件锁不会自动清除。若进程意外结束留下`.lock`，需要人工核对任务与页面回执后才能处理锁；不要直接删除任务状态来强行重跑。不同机器上的协调、分布式部署及远端文件系统不在本演示验证范围内。

真实UI验证已使用授权的内置浏览器，通过同一个执行器的IAB端口完成8项检查，详见VALIDATION.md。普通Playwright适配器便于在客户明确授权的浏览器环境中另行接入；该独立适配器未在本机实际运行，不能算成已验证的生产连接。

参考：[Playwright Locator](https://playwright.dev/docs/api/class-locator)、[BrowserType](https://playwright.dev/docs/api/class-browsertype)。

## 适用范围

这证明的是一个受限流程的执行、回执核验和失败停止设计。Facebook页面差异、权限、多账号隔离、上传视频、平台API额度、验证码、反机器人或账号风控均未测试；不承诺绕过这些限制。后续项目必须先确认实际环境、单个操作、合法授权和验收条件，再确定费用和维护范围。代码不提供浏览器凭据或外部账号访问。
